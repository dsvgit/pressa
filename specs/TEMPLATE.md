## Problem
What is broken or missing today, and what goes wrong if we do nothing.

## Goal
One paragraph. What this feature does when it works.

## Non-goals
What a reader might reasonably expect here and will not get. Be specific —
this section is what stops scope creep during implementation.

## User stories
As a <role>, I want <action>, so that <outcome>.

## UX
An ASCII mockup of every screen or state this touches. For a TUI spec this is
mandatory: it is what replaces a screenshot for an agent that cannot see.

## Domain model
Types added or changed, in Rust.

## API
Public function signatures this introduces.

## Invariants
Statements that must hold before and after every operation.

## Error cases
A table of input → error, with the exact message shape.

## Acceptance criteria
- [ ] Checkable, specific, one line each. The definition of done.

## Tests
Which tests prove which criteria: unit, integration, snapshot.

## Open questions
Anything that must be answered before this leaves Draft. An empty list is a
precondition for Approved.
